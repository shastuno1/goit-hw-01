# MLOps & PM Analysis: Iris Classification Experimentation

Цей репозиторій містить аналітичний звіт AI Product Manager за результатами ML-експериментів з класифікації ірисів та оцінці готовності моделі до деплою в Staging/Production.

## Короткий опис задачі
Аналіз 5 запусків (runs) у MLflow UI та метрик у Prometheus/Grafana для задачі класифікації ірисів (Iris dataset). Мета — обрати найкращого кандидата, перевірити audit trail та сформувати PM-рішення.

## Використані дані та скриншоти
* **MLflow UI:** Таблиця запусків, порівняльні графіки метрик, деталі запуску та артефакти `rf-depth3` і `rf-small`.
* **Prometheus / Grafana:** Графіки та табличний вигляд метрик `mlflow_accuracy` та `mlflow_loss`.

## Результати аналізу
* **Обраний кандидат:** `rf-depth3` (Run ID: `2ddc4f9d563c43e5a7c6c8523a580db3`).
* **Метрики кандидата:** Accuracy = **0.9556**, Loss = **0.1415** (краще за `logreg-baseline` з Accuracy 0.9333).
* **Model Artifact:** Збережено **тільки** для `rf-depth3`.

## PM-Рішення
**Go to Staging** для моделі `rf-depth3`.

## Ключові риски
1. Відсутність артефактів для інших 4 експериментальних запусків.
2. Відсутність регламенту Rollback та моніторингу Data Drift.

## Кроки перед Production
1. Провести тестування продуктивності та навантаження в Staging.
2. Автоматизувати збереження артефактів для всіх runs у CI/CD пайплайні.
3. Налаштувати алертинг у Grafana.
